> 阅读级别：进阶指南。先理解常规发送预览、收款金额和手续费。

钱包总余额可能包含许多来源、确认状态和隐私历史不同的独立币。币控制帮助你决定花费哪些币。但它也更容易让原本分开的资金意外关联，因此应带着明确目的使用。

<span id="inspect-and-select-coins" data-ginger-heading="查看并选择币" aria-hidden="true"></span>

## 查看并选择币

打开钱包菜单，选择 **Wallet Coins**。查看你持有的币的金额、标签、确认信息和隐私数据。一笔交易可以创建多个币，一个地址也可收到多笔独立付款；一行记录或一个地址都不一定代表整个钱包。

选择 **Send** → **Manual Control**，在付款流程中操作单个币。选择足够支付金额及手续费的价值。确认前核对最终输入和找零。选择币只是让交易构建器可以使用它们；查看最终预览，了解实际用了哪些。

保留说明资金来源或谁已经知道这些资金的标签。用已与同一收款人关联的币付款，可能比合并无关来源透露更少新信息。标签本身不会产生匿名性，也不会阻止别人的区块链分析。

<span id="consolidation-and-small-coins" data-ginger-heading="合并与小额币" aria-hidden="true"></span>

## 合并与小额币

合并将多个小额币花费为较少的输出，通常转入自己控制的钱包。现在需支付手续费，但可能减少以后付款所需输入数量。它也会公开关联选中输入。低费率时合并可能更便宜，但不会消除隐私取舍。

不要只为了币列表整齐就自动合并无关的币。极小的入账输出可能不值得花费。Ginger 的粉尘阈值与 CoinJoin 排除设置处理不同情况；将币排除在 CoinJoin 外，不会阻止你为普通付款选择它。

通过 **Send** 向硬件钱包转入资金，是普通链上交易。获取并验证新的硬件收款地址，然后检查软件钱包的手续费和选中币。转账本身在区块链上仍可见。

<span id="read-transaction-history" data-ginger-heading="阅读交易历史" aria-hidden="true"></span>

## 阅读交易历史

钱包首页显示入账、出账和 CoinJoin 活动。需要检查单个轮次时，展开分组的 CoinJoin 条目。排序控件帮助比较日期、金额、标签和状态。打开交易详情，查看交易 ID 和可用的确认或手续费信息。

需要标识具体交易时，使用 **Copy Transaction ID**。尽可能保密交易 ID：分享它可能披露地址、金额及与其他活动的关联。公开区块浏览器也会知道你的查询。Ginger 本地历史应是检查自己付款的首选位置。

可以查看、排序和分组历史，并复制交易 ID。本版本在该历史流程中没有交易搜索或 CSV 导出控件。

<span id="speed-up-an-unconfirmed-transaction" data-ginger-heading="加速未确认交易" aria-hidden="true"></span>

## 加速未确认交易

如果 Ginger 为历史条目提供 **Speed Up Transaction**，打开并在确认前检查额外手续费。根据交易和可用输出，加速可能将交易替换为更高手续费版本，也可能在子交易中花费某个输出，支付足以覆盖两笔交易的手续费。

钱包不能加速每笔交易。它需要受支持的交易结构，以及相关密钥和资金的访问。较高手续费提高矿工的处理动力，但不保证立即确认。替换可能改变交易 ID，因此与收款人沟通时，检查更新后的历史。

<span id="cancel-an-unconfirmed-transaction" data-ginger-heading="取消未确认交易" aria-hidden="true"></span>

## 取消未确认交易

如果提供 **Cancel Transaction**，它会尝试将待确认付款替换成一笔将相关资金返回你控制范围、并支付手续费的交易。它与原付款的确认竞争，不是所有节点都接受的撤销命令。

阅读取消对话框和手续费，仅在确实有此意图时确认，并监控哪笔交易实际确认。原交易先确认时，取消无法撤销它。付款确认后，如有需要，应向收款人请求单独退款；Ginger 无法取回资金。

在了解哪笔交易确认之前，不要发起第二笔付款或承诺退款。区块浏览器与钱包可能暂时显示不同的内存池信息，因为它们观察的是不同节点。
