公开收取比特币不需要公布钱包全部地址，但需要决定每位付款人或网站访客看到什么，再按需要分开无关收款。Ginger 支持普通链上接收和本地标签，不是开票服务器或网站自动轮换地址服务。

<span id="choose-how-to-give-out-addresses" data-ginger-heading="选择提供地址的方法" aria-hidden="true"></span>

## 选择提供地址的方法

| 方法 | 方便之处 | 暴露内容 |
| --- | --- | --- |
| 网站或个人资料上的一个永久地址 | 任何人无须联系你即可付款 | 可一起查看该地址收款及后续花费；页面将地址与所有者关联 |
| 向每个付款人提供新地址 | 每个付款请求有独立目的地 | 付款人和通信服务可能知道地址及身份；后续交易可能建立关联 |
| 每期定期付款提供新地址 | 可为每笔付款保留私人记录 | 需要传达新指示；付款人仍可能复用旧地址 |

公开地址收款不一定代表所有者总余额、收入或捐款人数。有人可向自己发送比特币，捐款人可重复付款，也可能存在其他地址。不要得出比可见交易所支持的更强结论。

<span id="receive-and-keep-useful-records" data-ginger-heading="收款并保留有用记录" aria-hidden="true"></span>

## 收款并保留有用记录

1. 打开目标钱包，选择 **Receive**。添加日后有助识别用途的标签，例如私密账单编号或相关活动。
2. 为该笔付款生成新收款地址。硬件钱包在可用时用 **Show on the hardware wallet** 在设备验证。
3. 通过目标渠道分享地址和约定的比特币链上金额。检查粘贴内容；不要只因聊天历史已有地址就复用。
4. 在 Ginger 核对实际收款和确认。付款人消息或付款截图不是钱包确认资金已到达。
5. 保留收款、标签与私人账单或捐款记录的对应关系。助记词不能重建全部笔记。

标签属于本地记录，不作为姓名发布在比特币交易中。但能读取本地文件、备份或共享屏幕的人可能看见。提供足以理解未来选币的细节，同时避免收集不必要的捐款人个人信息。

<span id="handle-a-permanently-published-address" data-ginger-heading="处理永久公开地址" aria-hidden="true"></span>

## 处理永久公开地址

使用永久捐款地址时，假设收款历史可以被查看。更换网站地址不会抹去旧地址，也不会阻止其将来收款。保留恢复资料和足以识别迟到收款的背景。

CoinJoin 在其假设成立时帮助减少与之后花费的关联；不会让公开地址的捐款消失。一次普通交易同时移动全部收款，可能增加新关联。像初次收款一样谨慎规划下一次花费。

订阅或客户重复付款，实际可行时每期提供新目的地。Ginger 不撤销旧地址，也不强制付款人遵循更新请求。承诺退款前，核对迟到和重复付款。

<span id="refund-the-payer-through-a-verified-destination" data-ginger-heading="通过已验证目的地退款" aria-hidden="true"></span>

## 通过已验证目的地退款

不要自动退到原付款某个输入地址。付款人可能使用交易所提现、托管服务或协作交易，未必控制那个输入地址。

1. 用私人记录及可信联系渠道确认原付款和退款请求。
2. 约定退款金额和谁承担手续费。向目标收款人取得新比特币退款地址，并通过该渠道核实。
3. 使用 **Send**，查看选中输入和手续费，仅授权约定付款。
4. 记录退款交易；网络错误后重试前检查结果。

退款是新的链上付款，不会撤销原收款或删除记录。考虑退款交易透露了你选择花费的币的哪些信息。

<span id="keep-receipt-handling-deliberate" data-ginger-heading="有意识地处理收款" aria-hidden="true"></span>

## 有意识地处理收款

打开 **Wallet Coins** 查看产生的币。**Send** → **Manual Control** 可帮助选择已与相关活动关联的资金。检查最终交易，不要认为标签自动强制分离。

意外小额付款不需要立即应对。花费小输出可能耗费很大比例价值，并将其与其他选中输入关联。**Exclude Coins** 仅影响 CoinJoin 参与，不会阻止普通花费。不要遵循未经请求的付款或联系人中声称必须发送资金才能解锁的指示。

如果将符合条件的 CoinJoin 输出发送到另一个已加载钱包存储，每次会话前检查选择。它在重启后重置；所有符合条件资金已经私密时，正常版本流程不会强制额外轮次。定期收款安排不应依赖未经验证的“所有资金持续转送硬件”假设。

具体示例继续阅读 [CoinJoin 后花费](/zh-cn/learn-privacy/spending-after-coinjoin/)，以及[信息分享](/zh-cn/learn-privacy/information-sharing/)，了解网站、区块浏览器和其他应用能知道什么。
