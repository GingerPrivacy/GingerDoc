> 阅读级别：进阶指南。确保基本恢复备份可用；根据暴露的信息采用对应事件处理步骤。

有用的安全习惯既防止未授权访问，也留下可理解的合法恢复路径。增加秘密却不记录各自作用，可能增加意外丢失概率。

<span id="record-the-recovery-plan" data-ginger-heading="记录恢复计划" aria-hidden="true"></span>

## 记录恢复计划

保留私密清单，记录各钱包、签名器类型、备份位置及是否需要 BIP39 口令。清单无须包含秘密本身。它应在电脑或手机丢失后仍有用，而不只在你还记得如何设置时有用。

保留足够钱包约定信息，以识别正确恢复账户，尤其是使用硬件或多个钱包时。标签和元数据对记录重要时，保留其备份；区块链不能重建你写的私人笔记。

如果计划让他人在你失去行为能力或去世后恢复资金，安排适合情况、清晰且经过测试的访问计划。避免现在随意分享全部秘密，也不要认为对方会猜到你指哪个密码。遗产和访问安排可能有需要当地专业建议的法律影响；本页不规定法律结构。

<span id="check-before-funding-and-before-signing" data-ginger-heading="充值前与签名前检查" aria-hidden="true"></span>

## 充值前与签名前检查

验证应用下载，确认钱包能打开，并检查备份。硬件钱包应在设备比对收款地址，并在签名前核对每笔付款目的地址和金额。

用小额学习新流程。核对发送金额、到达金额和支付费用。增大金额不会让不熟悉的流程更容易诊断。

通过已验证来源更新电脑和签名设备。私信更新通知不能证明文件合法。切勿仅因陌生人说币需要同步，就安装“恢复软件”或允许远程控制。

<span id="understand-ginger-2fa" data-ginger-heading="了解-ginger-2fa" aria-hidden="true"></span>

## 了解 Ginger 2FA

Ginger 可选 2FA 增加本地钱包文件加密，以及通过服务进行的启动验证。它可抵御部分本地文件访问，但让正常启动依赖身份验证器和服务。

助记词和原始口令须能独立取得。不要认为 `2fa_info.gws` 是离线主恢复密钥，也不要认为 2FA 能阻止已经持有助记词和口令的攻击者，或阻止已解锁应用中被授权的交易。

<span id="first-identify-what-was-exposed" data-ginger-heading="先确定暴露了什么" aria-hidden="true"></span>

## 先确定暴露了什么

地址披露与助记词披露需要不同应对。诊断时，避免把可疑资料复制到公开帖子或不熟悉的“钱包检查器”。

| 暴露项目 | 可能造成什么 | 首先应对 |
| --- | --- | --- |
| 一个收款地址或交易 ID | 观察该地址或交易并追踪可能关联；不提供签名密钥 | 停止不必要复用和进一步披露；检查哪些身份和付款被关联 |
| 标签、订单记录或钱包历史导出 | 将原本分离交易与人、用途或余额关联 | 限制访问，按需保留私人副本，并改变记录分享方式 |
| 扩展公钥，常称 xpub | 监控其派生范围内地址，可能包括未来地址；通常不能单独授权花费 | 确定受影响账户或分支；无法接受持续监控时考虑新钱包 |
| 钱包文件或整个应用数据副本 | 暴露取决于加密、可用密码及复制的其他文件；可能包含密钥和私人元数据 | 认真对待不确定性，从可信环境评估签名密钥暴露 |
| 助记词及所需口令，或可用私钥 | 花费资金并派生受影响范围内更多密钥 | 在可信设备准备新密钥钱包，并转移仍控制的资金 |
| 被盗电脑、已解锁应用或远程控制会话 | 根据状态，可访问钱包数据、签名操作和其他账户 | 终止未经授权访问，用可信设备评估并保护剩余资金 |

扩展公钥不一定能观察设备上每个账户；其派生范围重要。但在已披露公开分支下生成另一个收款地址，通常不能阻止继续监控该分支。[BIP32 描述这些公钥派生边界](https://github.com/bitcoin/bips/blob/master/bip-0032.mediawiki)。

如果只披露助记词而使用了独立口令，风险还取决于口令是否仍保密及猜测难度。不要认为未知或弱口令会让暴露备份无限期安全。证据不完整而暴露可能授权花费时，采用密钥暴露应对。

<span id="respond-to-exposed-signing-keys" data-ginger-heading="应对签名密钥暴露" aria-hidden="true"></span>

## 应对签名密钥暴露

更改电脑密码、关闭 2FA 或重装 Ginger，不会撤销复制的比特币密钥。重命名钱包也不改变密钥。比特币没有能取消复制助记词的客服流程。

1. 使用有依据可信的设备。原电脑可能被入侵时，不要在那里生成替代钱包。
2. 用全新恢复信息创建钱包，保护备份。不要恢复已暴露的助记词，再称恢复钱包为新的安全边界。
3. 获取并验证收款地址。硬件钱包在签名设备验证；切勿将新助记词输入可疑电脑。
4. 仔细核对目的地址和手续费，转移仍能控制的资金。同密钥攻击者可与你竞争；保护资金前避免增加可选 CoinJoin 等待。
5. 在可信钱包检查结果并监控确认。更换定期入账指示和旧公开收款详情，防止未来资金继续到达已受影响密钥。

转账可能产生可观察链上关联。密钥泄露时，保住资金控制权优先；即时访问问题受控后，可再考虑隐私。新目的地不保证转账无法关联。

调查时私下保留必要记录。切勿向所谓客服提供助记词、口令、无限制钱包文件副本或替代设备访问。新助记词无需在网站上“验证”。

<span id="respond-to-a-privacy-only-disclosure" data-ginger-heading="应对仅涉及隐私的披露" aria-hidden="true"></span>

## 应对仅涉及隐私的披露

地址暴露后，决定是否可接受继续使用。未来可以使用新地址收款，并避免公开额外交易详情，但观察者保留已知信息。不能仅因地址公开就自动认为必须移动每个币。

xpub 披露时，先确定它涵盖哪个账户。继续使用该账户可暴露未来活动。独立密钥的新钱包建立不同地址集合，但直接转账可明显将旧资金与其联系。根据观察者及其知识规划迁移和后续花费。重装钱包应用或在别处导入同一账户不会消除暴露。

记录泄露时，限制后续访问，并评估组合起来透露什么。交易 ID 配客户姓名比单独任一内容更有揭示性。不要为证明问题就公布完整泄露资料。

<span id="keep-privacy-separate-from-key-protection" data-ginger-heading="区分隐私与密钥保护" aria-hidden="true"></span>

## 区分隐私与密钥保护

观察者知道交易，不一定拥有花费密钥。反之，持密钥的小偷可花费历史难以分析的资金。恢复保护和设备验证用于后者；地址习惯、Tor、选币及经过考虑的 CoinJoin 用于前者。

添加钱包、更换硬件、启用 2FA 或移动备份后，重新检查安排。验证改变的部分，不要为不必要的完整恢复练习反复暴露每个秘密。
