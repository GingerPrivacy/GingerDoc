> Уровень: углублённое руководство. Сначала проверьте обычное состояние соединения и синхронизации.

Использование собственного узла Биткоин может уменьшить зависимость от публичных узлов для данных блоков. Оно также добавляет ответственность за хранение, пропускную способность, доступность и обслуживание. Вы можете использовать Ginger, не включая необязательный полный узел.

<span id="start-the-bundled-node" data-ginger-heading="запустите-встроенный-узел" aria-hidden="true"></span>

## Запустите встроенный узел

В **Settings** → **Bitcoin** переключатель называется **(EXPERIMENTAL) Run Bitcoin Core on startup**. Версия 2.0.26 включает Bitcoin Core 31. Используйте инструкции, соответствующие этому встроенному узлу и установленной версии.

1. Выберите **Bitcoin Core Data Folder** с достаточным пространством и надёжным хранилищем. Не указывайте постороннюю папку и не позволяйте двум процессам узла одновременно управлять одним каталогом.
2. Включите **(EXPERIMENTAL) Run Bitcoin Core on startup** и перезапустите Ginger, когда он попросит.
3. Дайте начальной синхронизации узла продолжаться. Следите за состоянием соединения и загрузки; первая синхронизация может занять много времени.
4. Установите **Stop Bitcoin Core on shutdown** в зависимости от того, хотите ли оставить узел работающим после выхода из Ginger.

Не включайте этот переключатель только ради исправления отсутствующего баланса кошелька. Узел не может восстановить неизвестную парольную фразу или метки. Существующий каталог узла может содержать ценную конфигурацию и собственные кошельки; сохраните его резервную копию перед сменой управляющего им приложения.

Полный узел может проверять блоки локально, но это не устраняет зависимости Ginger от координатора, 2FA, покупки/продажи и других сервисов. Он также не скрывает транзакцию, которую вы добровольно раскрываете бирже.

<span id="connect-to-an-existing-node" data-ginger-heading="подключитесь-к-существующему-узлу" aria-hidden="true"></span>

## Подключитесь к существующему узлу

При выключенном переключателе запуска встроенного узла **Bitcoin P2P Endpoint** позволяет указать контролируемый вами узел для загрузки блоков. Введите доступный хост и порт P2P. Для узла Bitcoin Core основной сети на том же компьютере обычная конечная точка — `127.0.0.1:8333`, если узел действительно слушает там. Это поле принимает адрес узла сети Биткоин, а не URL обозревателя блоков или учётные данные RPC.

Убедитесь, что узел разрешает соединение вашего кошелька и имеет необходимые данные блоков. Узел с обрезанным хранилищем может не сохранять старые блоки, нужные восстановленному кошельку. Если историческое сканирование останавливается, проверьте доступность, вместо того чтобы считать все конфигурации узлов взаимозаменяемыми.

Соединение с удалённым узлом имеет собственное сетевое раскрытие. Используйте узел и транспорт, которые понимаете; простая установка конечной точки не доказывает приватность каждого соединения с ней. Избегайте открытия административного доступа RPC в публичный Интернет ради работы подключения кошелька.

<span id="choose-fee-estimates-separately" data-ginger-heading="отдельно-выберите-оценки-комиссий" aria-hidden="true"></span>

## Отдельно выберите оценки комиссий

**Fee Rate Provider** предлагает **Mempool Space**, **Blockstream Info** и **Full Node**. Публичные поставщики предоставляют оценки из своего представления условий сети. Выбор полного узла требует работающей интеграции узла/RPC Ginger; ввод одной конечной точки P2P не доказывает настройки оценки комиссий через RPC.

Когда выбран **Full Node**, но узел недоступен, v2.0.26 сообщает о недоступности оценки комиссий и всё равно позволяет ручной ввод при оплате. Можно дождаться узла, выбрать работающего поставщика оценок или ввести ставку, которой есть основания доверять. Не используйте огромную комиссию как универсальное исправление соединения.

Оценки комиссий — прогнозы, а не резервирование пространства блока. Разница между поставщиками может отражать разные наблюдения мемпула. Проверяйте общую комиссию транзакции вместе с отображаемой ставкой.

<span id="dust-threshold" data-ginger-heading="порог-пыли" aria-hidden="true"></span>

## Порог пыли

**Dust Threshold**, также в **Settings** → **Bitcoin**, управляет обработкой очень маленьких полученных сумм кошельком. Он отличается от правил ретрансляции сети, порога остановки CoinJoin и минимальной суммы входа координатора. Его повышение может влиять на то, какие небольшие платежи обрабатывает кошелёк; оно не удаляет их выходы из блокчейна и не препятствует отправке. Сохраняйте прежнюю настройку при расследовании неожиданно отсутствующего небольшого платежа.
